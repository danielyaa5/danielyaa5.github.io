# Daniel’s portfolio

A static portfolio hosted on GitHub Pages. The site uses HTML, CSS, and a small script for the About dialog, with no build step. Its only outside script is PostHog's, for anonymous page views on the published site (see Analytics).

The cream and green layout and illustrations follow the selected Quiet Utility mockup. Illustration files are stored locally in `assets/illustrations/` so the published page does not depend on temporary Canva links.

The artwork uses high-resolution WebP files with transparency. The pages load smaller display copies named after the width, such as `hero-800.webp`, so phones don't download 1,500-pixel art for a 240-pixel slot. Make one with `python3 tools/resize-image.py assets/illustrations/<name>.webp <width>`, choosing the larger of twice the widest size the art is shown at on desktop and three times the widest on phones, and keep the full-size file as the source (the social card uses it). Give the page's main image `fetchpriority="high"` and art below the first screen `loading="lazy"`. The home hero also has an AVIF copy (`hero-800.avif`, about half the size) in a `<picture>`, with the WebP as the fallback; the Pillow that ships with recent Python saves AVIF with `image.save(path, 'AVIF', quality=60)`. The corner mark, a wrench growing out of grass, is inline SVG line art in each page that shows it (home, resume, motorcycle rentals), so CSS can color it for dark mode and animate it: on hover or keyboard focus its outline redraws in green from the roots up (each shape has a trace copy whose dash pattern is that path's length; regenerate those lengths if the drawing changes). With reduced motion the outline turns green without drawing. It links to Zen and the Art of Motorcycle Maintenance on Goodreads. `assets/illustrations/wrench-grass.svg` is the same drawing as a file, used by the social card; the favicon is a separate 128-pixel PNG: the wrench and grass as a solid cream shape on a green rounded tile, so it stays visible at 16 pixels on light and dark browser tabs (its source is in the project's favicon options, not this repo). Bump the `?v=` on the favicon links when it changes, since browsers cache tab icons hard. The chain, App Store, and Chrome icons are from Tabler Icons; their shared license is stored in `assets/illustrations/link-LICENSE.txt`.

## Tiles

Every project tile (Featured and Other projects) and every Writings card on the home page opens from anywhere on the tile, not only its title. The title link is the tile's main link: its `::after` stretches over the whole tile, so clicks, middle-clicks, right-click menus and the link preview all use its address, and screen readers still hear one link per title. The tile's other links (the store, GitHub or Explore link, the star badge and Read article) sit above that layer with `position: relative; z-index: 2` and keep their own addresses (the layer itself is `z-index: 1`, so art that dark mode's filter lifts into its own layer stays under it). When a tile gets a new link, give it the same so it stays clickable. Hovering the tile underlines the title and darkens the tile's border; keyboard focus on the title rings the whole tile. A tile's main link is its title link, so change the title's `href` to change where the tile goes.

After changing tiles, run `node tests/tiles.cjs http://localhost:4173`. At phone, tablet and desktop widths, in light and dark mode, it checks that the art, description and empty corners of every tile hit the title link, that each other link in a tile is still on top and keeps its address, the hover and keyboard focus styles, and that clicking a tile's description opens its title's address. Screenshots of a hovered and a focused tile go to `test-results/tiles-*.png`.

`motorcycle-rentals/` lists the motorcycles Daniel rents out, one tile per bike, with booking links to each bike's listing on Riders Share and, where it's listed, Twisted Road. The navigation's Motorcycle Rentals link opens it. Riders Share links are the listing's **Share** link, which carries Daniel's referral code, not the plain listing address. ## Dark mode

The site follows the visitor's system setting. Light colors stay where they are in each stylesheet; a `@media screen and (prefers-color-scheme: dark)` block at the end of `styles.css` (and of `blog/blog.css`, `resume/resume.css` and `motorcycle-rentals/rentals.css`) swaps them for the forest-night palette: page `#0e1511`, cards `#17221b`, cream text `#ebe8da`, mint links `#98d4a8` and green filled buttons `#2a6b47`. In dark mode `--green` is the text accent, so anything filled uses `--fill` instead. Print stays light.

The illustrations aren't duplicated. The `--line-art` CSS filter turns their dark outlines and cream fills into quiet sage line art, and it applies to the hero, project and featured art and any image with the `line-art` class (illustrated blog thumbnails and covers; leave screenshots and photos without it). Art drawn on a white square instead of transparency gets `art-on-white`, which multiplies in light mode and lightens in dark mode. The Tabler icons are recolored with a filter. The corner mark sets its own dark colors (`--mark-*` variables), matched to what the filter gives the other art.

A new page needs `<meta name="color-scheme" content="light dark">` and the two `theme-color` tags (light `#fdfaf3`, dark `#0e1511`), and any colors its own stylesheet sets need a dark version. Check new work with Playwright's `colorScheme: 'dark'` as well as light.

## Analytics

`analytics.js` counts page views, clicks on links, buttons, filters and form fields (never what is typed), rage clicks, resume downloads, app download clicks and email sign-ups, and measures page speed (web vitals), with PostHog's US cloud in cookieless mode: no cookies or browser storage, no person profiles, no session recordings. It runs only on `danielyakobian.com` and `danielyaa5.github.io`, never on local previews. Addresses on this site are sent without their query string or fragment, including the ones inside web vitals and link click details; campaign tags such as `utm_source` are kept as their own properties. The guest gate page (`gate/`) and QuickDesk's privacy policy don't load it. New pages add `<script src="/analytics.js?v=17" defer></script>` to their `<head>`; raise the `v` number on every page when `analytics.js` changes so browsers fetch the new copy. On danielyakobian.com it reaches PostHog through the site's own `/dy-relay/` path, which `vercel.json` rewrites to PostHog's US hosts, so ad blockers that block PostHog's domains don't drop the counts; the GitHub Pages copy talks to PostHog directly.

Every link opened from a project tile on the home page also sends a `project_click` event with these properties:

- `project`: the tile's project name, such as `Cloud Media Shrinker`
- `link`: `title` for the project name, `tile` for a click anywhere else on the tile that opens the same link (see Tiles), `button` for the tile's store, GitHub or Explore link, `stars` for the GitHub star badge
- `link_text` and `destination`: the link's words and address
- `section` and `position`: `featured` or `other`, and the tile's place in that section, counting from 1
- `filter`: for Other projects tiles, the filter that was on (`all`, `mac`, `ios`, `web`, `developer` or `printing`)

Middle-clicks count too; opening a link from the right-click menu doesn't. The **Project tile clicks** insight in PostHog charts these events by project.

Every click on a link to the resume PDF sends a `resume_download` event with `button` (`top` for the button under the name on `resume/`, `scroll_bar` for the one in the bar that slides in on scroll, `end` for the one in the last section, `other` for any other resume PDF link), `link_text` and `destination`. Middle-clicks count too. Opening the PDF's address directly, or from the right-click menu, isn't counted. The **Resume downloads** insight in PostHog charts these events by button.

Every click on an app page's download button (a link with `data-store`, on `cloud-media-shrinker/` and `3d-print-monitor/`) sends an `app_download_click` event with `app` (the page's folder, such as `cloud-media-shrinker`), `store` (`app_store`, `direct` for the free Mac download, or `polar` for its license key), `placement` (`hero` for the buttons under the headline, `end` for the closing box, `whats_new` for a version's release rows on Cloud Media Shrinker's What's new page, `other` elsewhere), `link_text` and `destination`. Middle-clicks count too. These buttons carry the `ph-no-capture` class so PostHog's click autocapture doesn't record the same click again. The PostHog actions **CMS direct download click**, **CMS App Store click** and **CMS download click (any store)** count these events plus the autocaptured clicks from before the event existed, and feed the **Cloud Media Shrinker downloads** dashboard. Clicks are not purchases: sales are in Polar and App Store Connect.

The PostHog project must keep **Settings > Project > Web analytics > Enable cookieless tracking** on, or PostHog drops these events. The project token in `analytics.js` is public by design. Cookieless mode has no country data, and a visitor who returns on another day counts as a new visitor.

After changing analytics or adding a page, run `node tests/analytics.cjs http://localhost:4173`. It checks which pages load the script, then simulates the published host with PostHog's real script, intercepts its requests so nothing is sent, and checks the page view, its cleaned address, the web vitals event and the addresses inside it, a `project_click` from a featured and a filtered tile and the email sign-up events at phone, tablet and desktop widths, and the untracked gate page. Set `POSTHOG_ARRAY_JS` to a local copy of PostHog's `array.js` if its CDN is unreachable (`npm pack posthog-js` and use `package/dist/array.js`); the test serves the web vitals script from the same folder.

## Monitoring

- **Rage clicks:** 3 or more clicks within 1 second inside a 30 px circle, on any element, send one `$rageclick` with `element` (tag, id and up to three classes), `element_parent`, `element_text` (first 80 characters) and `link` when inside a link. `analytics.js` detects these itself because PostHog's built-in detection only counts clickable-looking elements, which misses something that looks clickable but isn't; PostHog's own `rageclick` option stays off so nothing is counted twice. At most 10 per page.
- **Browser errors:** uncaught errors and unhandled promise rejections are sent as PostHog `$exception` events and grouped under **Error tracking**, with `error_source` (`uncaught` or `unhandled_rejection`). `analytics.js` listens from the moment it runs, so errors raised before PostHog loads wait and are sent once it is ready; PostHog's own exception autocapture stays off so nothing is counted twice. Errors from browser extensions and cross-origin `Script error.` reports are skipped, and a page sends at most 10.
- **Page speed:** `analytics.js` sends PostHog's `$web_vitals` event (LCP, INP, CLS and FCP, with the element behind a slow LCP or INP). See them per page under **Web analytics > Web vitals** in PostHog. With a few dozen visits a week, give the numbers a few weeks before reading much into them.
- **Uptime:** `.github/workflows/uptime.yml` runs `.github/scripts/uptime.cjs` every 15 minutes. It checks the home, resume, rentals and blog pages, `analytics.js`, that the sign-up function answers a GET with its 405, the `www` redirect, the TLS certificate (at least 14 days left) and the GitHub Pages copy, retrying a failed check twice 20 seconds apart. When a check still fails it opens a **Site check failed** issue that mentions `@danielyaa5`, so GitHub emails the owner, and posts to the `#alerts-danielyakobian-com` Slack channel through the `SLACK_ALERTS_WEBHOOK` repository secret (when the issue opens and when it closes, not on each update); the issue's table is updated while checks keep failing, and it gets a "Back up" comment and closes itself once they all pass. Run the workflow by hand with **test_alert** ticked to check that the issue and email arrive; the next scheduled run closes the test issue. GitHub turns scheduled workflows off after 60 days without commits to the repository, and may start a run a few minutes late. `node .github/scripts/uptime.cjs` runs the same checks from a terminal without touching issues.
- **Failed deploys:** `.github/workflows/deploy-alert.yml` posts to `#alerts-danielyakobian-com` when Vercel's commit status for a commit on `main` turns to failure or error, with the commit and a link to the build log. A failed deploy leaves the previous version live, so the uptime check can't catch it. Other statuses skip the job; run the workflow by hand to post a test message.
- **Alerts in PostHog** (emailed to the owner and posted to the `#alerts-danielyakobian-com` Slack channel; the plan allows 5, so related events share one alert and the email says only that something happened, with the details on the **Overview** dashboard): **Needs a look** checks hourly and fires on any `$exception` (details under **Error tracking**), `$rageclick`, or `email_signup_failed` other than a mistyped address in the last finished hour, so one error sends one alert instead of one every hour until midnight UTC; **Good news** fires once a day when the day before had an `email_signup`, a `resume_download` or a Cloud Media Shrinker direct download click; **No site visitors in a day** fires when a whole day has no page views, which usually means tracking broke; **Traffic spike** fires when a day's visitors are more than triple the day before; **Slow page loads (LCP p75)** fires when the week's 75th-percentile LCP is over 2.5 seconds. **Overview** is the project's home dashboard.

## Email sign-up

Below Featured projects, visitors can sign up for emails about beta tester invites (try apps early and get them free for life), new app and open source launches, and promos. The 3D Print Monitor page has its own form, for an email when the app can be downloaded and when new versions ship. Both forms post to `api/subscribe.js`, a Vercel function served at `danielyakobian.com/api/subscribe/`. GitHub Pages can't run it, so the copy on `danielyaa5.github.io` posts to `danielyakobian.com` too; the function allows both origins. Without JavaScript the form still posts, and the function sends the browser back to a `#signup-thanks` or `#signup-failed` message on the page named in the form's hidden `return` field (only `/` and `/3d-print-monitor/` are allowed; anything else goes to the home page).

`signup.js` runs every `.signup-form` on a page. A form's topics are its ticked boxes plus any hidden `topic` field. After a successful sign-up the section shrinks to one line, "Signup success!" (or the form's `data-done` text), with an **Edit email** button that brings the form back. The browser keeps an entry in local storage with the topics (never the address) so the section stays small on later visits; Edit email removes it. Each form has its own key (`signup-done` on the home page, the form's `data-remember` elsewhere), so signing up on the 3D Print Monitor page doesn't hide the home page's form. Nothing in it is sent anywhere.

Sign-ups are stored as contacts in Resend. Each box is a Resend topic (**Beta tester invites**, **New app and open source launches**, **Promos**), and the 3D Print Monitor form sends **3D Print Monitor updates** (`print_monitor`). The function creates all four on first use with an opt-out default, so a contact only gets the topics they signed up for, and 3D Print Monitor sign-ups stay apart from the rest. To email them when a version ships, send a Resend broadcast to the **3D Print Monitor updates** topic. To rename a topic, change its `name` in `api/subscribe.js` and add the old name to `formerly`; the function renames the existing topic so its subscribers stay on it. Send to a topic by choosing it in a Resend broadcast; recipients can change topics from the unsubscribe link in every broadcast. Signing up again with the same address adds the newly ticked topics and turns email back on. A hidden `company` field catches bots.

The function needs `RESEND_API_KEY`, a Resend API key with full access, set in the Vercel project's environment variables for Production and Preview. Without it the form tells visitors sign-ups aren't open yet. Sending broadcasts from `danielyakobian.com` also needs the domain verified in Resend.

A successful sign-up sends an `email_signup` PostHog event with `topics`, `topic_count` and a true/false property per home page topic (`new_apps`, `beta`, `promos`); 3D Print Monitor sign-ups show as `topics` containing `print_monitor`. A failed one sends `email_signup_failed` with an `error` code. The address is never sent to PostHog.

After changing the form, run `node tests/signup.cjs http://localhost:4173`. At 13 widths it checks that the form sits between Featured projects and Other projects, lines up with the tiles, stays in its card and has 44-pixel touch targets, then fills it in against a fake function: empty and topic-less sign-ups, a successful one with the one-line success state, its reload and Edit email, each error message, and the no-JavaScript path. Screenshots go to `test-results/signup-*.png` and `test-results/signup-done-*.png`. After changing the function, run `node tests/subscribe-api.cjs`, which runs it against a fake Resend API. `node tests/print-monitor.cjs http://localhost:4173` covers the 3D Print Monitor form end to end: the browser's post is answered by the real function running in the test with a fake Resend API, so it checks that an address lands on the 3D Print Monitor topic only, the per-form storage key, an address the function rejects, and the no-JavaScript return to the 3D Print Monitor page.

## Publish

GitHub Pages publishes the root of the `main` branch, and Vercel deploys the same branch to `danielyakobian.com`. Update `index.html` and `styles.css`, verify the affected layout, and push to `main`.
